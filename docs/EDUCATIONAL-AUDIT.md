# Educational audit · 23 October 2026

This audit inspects the personal school's actual lesson objects, study guides, assessment rules, project briefs, persistence code and authored tests. The baseline contains 61 released lessons (22 foundation, 14 advanced bridges, 24 expanded, one AWS field checkpoint), 22 sections, eight projects and 12 certification checkpoints. A section title, resource link, self-check or backlog entry is not proof of taught or independently demonstrated competence.

The audit's additions are two bounded lessons (`python-cli`, `network-cidr`) and 28 original certification questions. The combined release also introduces a six-month roadmap and project milestones. April 2027 is an aspirational review point; evidence and prerequisites determine pace. No deployment, merge, account operation, resource creation, paid purchase or learner-record inspection formed part of this audit.

## Evidence and classification

Primary inspected owners: `src/content/{foundations,advanced,expanded,index,study-guides,guides-foundations,guides-advanced,guides-expanded,projects,certifications}.ts`, `src/lib/{learning,gates,storage,drafts}.ts`, `src/components/{Pages,Practice}.tsx`, `tests/{content,learning,gates,storage}.test.ts`, and `tests/e2e.spec.ts`. Documentation was used to locate intended depth, then checked against those owners. The exact checks executed for this release belong in the final verification record; an authored test is not a passing test result.

**Implemented and verified** means a bounded claim has direct source and executed evidence. **Incomplete** means useful teaching exists but the requested capability still has material gaps. **Documented-only** means a description, request or future brief exists without its working learning sequence. **Missing** means no usable implementation was found. **Blocked/unverified** identifies proof this session cannot establish. These labels apply to specific scope; none certifies a learner or a whole professional discipline.

## Highest-priority sequencing

1. Preserve existing learner evidence and establish a clean-release test result before changing progression or storage. No prior history becomes fresh competence automatically.
2. Close address-planning and CLI prerequisites locally, then use the new question explanations to reveal gaps in IAM, billing/support, storage/database selection, queues and recovery objectives.
3. Turn the strongest existing local projects into milestone-based evidence with one genuinely fresh reproduction and one unfamiliar fault. This improves interview evidence sooner than adding more service names.
4. Prepare, but do not execute in this session, a reviewed IAM/EC2/VPC/S3 field sequence with current pricing, workload identity, request/denial checks, inventory and cleanup. Extend to RDS/ALB and queues only when the prerequisite record is credible.
5. Integrate one small system through Terraform, persistent containers, protected delivery, telemetry and recovery. Defer broad Kubernetes specialization until this foundation is independently reproducible.

## New teaching, sources and proof limits

The question bank is original Atlas-authored material, not recalled exam questions or a licensed exam product. Four options have exactly one intended best answer; each option has a rationale. Domain coverage is 3/4/4/3 for CLF-C02 and 4/4/3/3 for SAA-C03, in official domain order. This is deliberately a short teaching set with reusable visible questions, not a full timed mock, exhaustive objective map or pass prediction. A score on a repeated set must not be logged as unseen exam-readiness evidence. Lesson links identify preparation foundations; they do not claim the linked lesson already teaches every service in the scenario.
